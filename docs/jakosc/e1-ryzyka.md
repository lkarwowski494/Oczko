# Rejestr ryzyk roli 07 (E1, build) · 2026-10-25

Scalone cztery niezależne soczewki: dane (SD-01–SD-111), programista (PG-01–PG-53), wydanie (WY-01–WY-44), sceptyk (SC-01–SC-30); razem 238 ID. Każde ID trafiło do dokładnie jednego wiersza R (tabela pokrycia na końcu, sprawdzona skryptem `generuj-rejestr.py`). Kwarantanna: tylko `CLAUDE.md`, `docs/`, `tests/wektory/brd.json`, raporty soczewek i klon Treningu; repo bez zmian.

**Skala.** S1: utrata lub zepsucie danych, prywatność, bezpieczeństwo, główny przepływ nie działa, odrzucenie w sklepie, płacący bez dostępu. S2: błędna liczba lub twierdzenie, funkcja poboczna, zły stan po powrocie z tła, bariera dostępności. S3: szlif, przypadek graniczny o małym skutku. Przy scaleniu wierszy bierzemy wyższy skutek i wyższe prawdopodobieństwo z soczewek, chyba że opis mówi inaczej. Sceptyk nie podawał prawdopodobieństwa: dla jego ID ocena roli 07 przy scalaniu.

**Priorytet.** wysokie = S1 realny lub brzegowy (a dla danych, prywatności, bezpieczeństwa także teoretyczny) oraz S2 realny; średnie = S2 brzegowy i S3 realny; niskie = reszta.

**Potwierdzone przez rolę 07 (traktowane jako fakt):** mutant `<`→`<=` w `limit.mjs:32` przeżywa 35/35; wektory RD-16 tylko w czasie letnim; strażnik limitu nie zna `cofniecie`/`rozstrzygniecie` (mapowanie `moduly.md:77` bez testu); cytat Apple o środowisku Production CloudKit; `scal.mjs`: 3 stuknięcia z tym samym rodzicem → konflikt 23/23/23 zamiast 25; `scal` przy 10 000 zdarzeń → „Maximum call stack size exceeded”.

**Odsyłacze.** `e3-…md` = `docs/architektura/e3-tlo-bledy-prywatnosc-wydajnosc.md`; A1–A4 = strony Apple odczytane przez soczewkę wydania (teksty w `scratchpad/e1/src/`); ER-37–ER-44 i Z07-07–Z07-21 = `docs/jakosc/e1/zgloszenia-e1.md`; „pytanie N” = `docs/jakosc/e1/pytania-e1.md`; ER-34–36 i Z07-01–06 = istniejące wpisy `docs/jakosc/zgloszenia.md`.
