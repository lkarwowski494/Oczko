# Soczewka „programista jutro”: gdzie zmiana przejdzie bez czerwonego testu (rola 07, E1, 2026-10-25)
Perspektywa: osoba, która jutro zrobi refaktor, migrację, zmianę parametru, kolejności w transakcji, nowy ekran, tekst, aktualizację zależności, zmianę Swift (zegarek, intencja), workflowu CI albo podpisu i liczy, że czerwony test ją zatrzyma.
Źródła: tylko `docs/` (lista z zadania) i `tests/wektory/brd.json`. Kodu `src/`, `tests/`, `scripts/`, `app/` nie czytałem. Nic w repo nie zmieniłem.

**Dowód z mutantów (kopie w scratchpadzie, `e1/mut/mutuj.mjs`, testy z repo bez zmian):** 18 ręcznych mutantów `limit.mjs`, `dostep.mjs` i `scal.mjs` sprawdzonych istniejącymi testami wektorów. **Przeżyło 7:**
- `limit.mjs:32`: `<` przerwa → `<=`
- `limit.mjs:47`: `!pro && zostalo === 1` → `zostalo === 1`
- `dostep.mjs:24`: `>` → `>=`
- `dostep.mjs:31`: `>` → `>=`
- `dostep.mjs:26`: `Math.max` → `Math.min`
- `scal.mjs:12`: bez `.sort()`
- `scal.mjs:18`: `rodzice[0]` → ostatni rodzic

Polecenie: `node <scratchpad>/e1/mut/mutuj.mjs <scratchpad>/e1/mut`.

Skróty:
- **S:** S1, S2 albo S3, jak w zadaniu.
- **P (prawdopodobieństwo):** R = realny, B = brzegowy, T = teoretyczny.
- **Poziom kontroli:** G = grep albo skrypt w CI, N = test Node, Q = `node:sqlite`, RNTL, X = XCTest albo `swift test` (macOS), E = E2E Maestro albo XCUITest na symulatorze.
- **Pokrycie:** numer z listy roli 05 (`e3-…md:39–51`, 1–13), kontrola roli 12 (`niezawodnosc/e1-decyzje.md:35–36`) albo 09 (`lokalizacja/e1-mechanizm.md:85`). **LUKA** = żadna z tych list tego nie obejmuje.
